UI 层应该解决什么

UI 不是简单地把 Prefab 堆上去，而是负责输入、状态展示和数据映射。整理版文档只保留最实用的三层模型：页面控制器、通用组件、数据绑定适配层。

建议结构

  • Page：负责生命周期、页面切换、状态编排。
  • Widget：负责局部复用，比如列表项、弹窗、提示条。
  • Binding：负责把运行时数据投射到文本、按钮、图标和动画。

实践准则

  • 页面脚本不直接查找全场景对象，依赖统一注入或初始化入口。
  • 列表项只关心单条数据，列表控制器统一处理增删和刷新。
  • UI 状态优先走显式枚举，不要把多个布尔开关拼在一起。
public sealed class InventoryPage : UIPage
{
    public override void OnOpen(PageArgs args)
    {
        BindToolbar();
        RenderItems();
    }
}
